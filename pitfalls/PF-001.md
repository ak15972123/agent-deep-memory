# PF-001: WSL2 默认 Node 版本过旧及 Root 下 npm 全局权限拒绝

## 1. 陷阱场景与失败链
- **环境**：WSL2 Ubuntu 22.04 (运行在 Windows 宿主机上)。
- **操作**：尝试在 Root 环境下为了越界执行 OpenClaw 而运行 `npx pnpm build` 或 `pnpm install`。
- **错误表现**：
  ```
  npm WARN EBADENGINE Unsupported engine {
    package: 'pnpm@10.30.3',
  ... current: { node: 'v12.22.9', npm: '8.5.1' }
  sh: 1: pnpm: Permission denied
  ```

## 2. 根源分析
1. **Ubuntu 官方源落后**：Ubuntu 22.04 的 APT 仓库自带的 `nodejs` 是上古的 `v12.22.9`，而当今的脚手架和 pnpm 强制需要 `>=18.12`，触发 `EBADENGINE`。
2. **Npx 沙盒拦截与权限拒绝**：在 Node 12 的上古架构中，Root 使用 `npx` 执行一个不在本地系统内的临时远程脚本或者全局包（且跨越 /mnt/c/ 的宿主盘符）时，会因为文件权限位 (`sh: 1: pnpm Permission denied`) 直接阻断执行流。

## 3. 正确解决方案 (正解)
不要使用原生 `apt-get install nodejs`，必须彻底铲除它，并通过 NodeSource 强插 LTS 22.x 版本。

解决方案命令流：
```bash
# 1. 彻底清空旧版本 nodejs 与 npm
sudo apt-get remove -y nodejs npm libnode-dev
sudo apt-get autoremove -y

# 2. 从 NodeSource 注入最新 LTS Node 22 环境
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs

# 3. 稳妥起见，直接安装全局 pnpm
npm install -g pnpm

# 4. 最后验证环境是否及格
node -v
pnpm -v
```
